## Games as Systems

- Set of formal elements, when set in motion create a dynamic experience in which players engage
- Can be simple or complex, predictable or unpredictable
- Basic elements of systems:
  - Objects: basic building blocks, physical and/or abstract, game pieces or concepts, players, areas or terrain, defined by properties, behaviours, and relationships with other objects
  - Properties: qualities/attributes that define physical/conceptual aspects of objects, sets of values that describe an object (e.g., colour, location, health, strength, level, experience)
  - Behaviours: potential actions an object might perform in a given state (e.g., moving, fighting, using items), more behaviours = less predictable, more complex not always better
  - Relationships: between objects, central to a system, without relationships objects are collections, based on location, hierarchy, sequence, changes in the game, player choices, determined by chance or rule sets

<aside class="slide-aside">

- Systems exist throughout the natural and human-made world.
- Complex behaviour emerging from the interaction of discrete elements.

</aside>

## System Dynamics

- Whole is more than the sum of its parts. Games can only be understood during play
- We cannot directly determine the player experience, we craft a possibility space and playtest it as rigorously as possible
  - Each playthrough can be different
- Gameplay, like story, can have structure that varies from linear to emergent
  - Depend on how the objects, properties, behaviours are defined
  - Simple objects can give rise to a complex system if they are highly interconnected and interdependent
  - Emergence = properties, behaviours, and structure that occur at higher levels of a system, which are not present or predictable at lower levels
  - Emergent gameplay in The Sims, SimCity, Black & White, Spore, GTA, Half-Life

## Designing for Interaction with Systems

- Considerations:
  - How much information do players have about the state of the system?
  - What aspects of the system do players control?
    - How is that control structured?
  - What type of feedback does the system give the players?
  - How does this affect the gameplay?

## Information Structure

- Players need info on the state of game objects and their current relationships to make choices about how to proceed
  - Less info = less informed choices / control over progress
    - Increased chance, space for misinformation / deception
  - Do players need to know the effect of every move they make? Other players? Is info always available?
- Open information structure
  - Classic games (Chess/Go) = complete information
  - Emphasises player knowledge, calculation-based strategy
- Hidden information structure
  - Hidden info about opponent's state (e.g., poker)
  - Play includes guessing, bluffing, deceiving, social cues
- Mixed information structure – some open / hidden info
- Dynamic information structure – changes during play

## Control

- Players control game systems by interacting with control systems
  - Keyboard, mouse, console controller, gesture, touch, speech
  - Needs to be well-suited to the game experience
- Players can control the game system/state by:
  - Direct control of movement in the game world
  - Selection of items, interacting with menus/options
  - Indirect control to influence the game state – setting variables
- Choice of controls forms the top-level player experience
  - Repetitive process/action performed throughout the game
  - If it's hard, unintuitive, or not enjoyable – player might quit
- Consider controls when designing/deciding on conflict
  - What can / can't the player control and to what extent?
  - What happens if control is given vs taken away?
- More next week when we talk about Game Interface Design

## Feedback

- Direct relationship between the output of an interaction and a change to another system element
- Positive or negative, reinforcing or balancing
  - Gain something when doing well = positive feedback loop
  - Lose something when doing well = balancing effect
  - Lose something when doing poorly = negative feedback loop
  - Gain something when doing poorly = balancing effect
- Reinforcing loops can be used for satisfying gameplay
  - Escalating risk/reward scenarios based on player choices
- Balancing effect – use to balance the game/players
  - Not fun if one player gets too far ahead

## Interaction Loops

- Interaction steps within a game:
  - Player starts with a mental model that prompts them to ...
  - Make a decision to ...
  - Apply an action in order to ...
  - Manipulate the game rules and in return ...
  - Receive feedback that ...
  - Updates their mental model..
- In other words, they start to learn how the systems of the game work
- Players then start the interaction loop over again to gain more practice with a specific skill.
- Mastery only arises after repeated passes through each of the steps.
- Each time they sample the system, they gain more info on how it behaves.

## Interaction Loops

- Skill chain: mastering simple interactions allows players to complete compound interactions
- Interaction loops occur at different frequencies, or time scales – helps to understand pacing
- Thinking in terms of interaction loops can help structure how a player will build their wisdom about a game
  - A holistic, intuitive understanding of a complex system
- Interaction Arcs
- Used to deliver evocative content like a story
  - Similar structure to interaction loop
  - Player starts with a mental model, apply an action to a system of rules and receives feedback
  - Mental model is updated with evocative stimuli
  - Goal is to convey ideas as efficiently/effectively as possible
