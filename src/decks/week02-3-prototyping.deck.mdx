## Productive Prototyping


### Ten Tips for Productive Prototyping

- Answer a question – articulate your questions clearly
- Forget quality – quick and dirty throwaway work
- Don't get attached – plan to throw them away
- Prioritise prototypes – consider dependencies, importance
- Parallelise prototypes productively – art/design/tech
- It doesn’t have to be digital – paper prototyping
- It doesn't have to be interactive – sketches/animations
- Pick a "Fast Loop" Game Engine – make changes while the game is running (Unity)
- Build the toy first – make it fun to play with
- Seize opportunities for more loops – if you have time

- If my game had no goal, would it be fun at all? If not, how can I change that?

## Physical Prototypes

- Easy to construct, easy to change or throw away
- Use paper, cardboard, household objects, drawings
- Focus on gameplay and not technology
- No special knowledge or expertise
- Low cost and use of resources
- Don’t worry about look and feel or artwork
- Play board games – you have to think through mechanics
- Building/revising paper prototypes instills a deep understanding of game principles
- Allows you to:
  - Build a structure for a game
  - Think through how different elements interact
  - Formulate a systemic approach to how the game will function

## Prototyping your game idea

- Start with the core gameplay mechanic
  - The actions that a player repeats most often while striving to achieve the game's overall goal
  - Games are repetitive by nature, core actions stay the same and are built upon over the game
  - Diagramming core game actions can help spot problems early on (e.g., feedback loops)

<aside class="slide-aside">

- Core gameplay examples
- WarCraft III: Players build and move units on a map in real time with the intent of engaging opposing units in combat and destroying them
- Diablo III: Players battle monsters, seek treasure, and explore dungeons in an attempt to amass wealth and become more powerful

</aside>

- Core gameplay examples
- Monopoly: players buy and improve properties with the goal of charging rent to other players who land on them during play
- Super Mario Bros.: A player controls Mario, making him walk, run, and jump, while avoiding traps, overcoming obstacles, and gathering treasure

## Prototyping your game idea

- Building the Physical Prototype
  - Foundation, Structure, Formal Details, Refinement

### 1. Foundation (build a representation of core gameplay)

  - Goal: designing basic game objects and key procedures
  - Draw a board layout or map, use arts/crafts to make pieces
  - Questions will arise as you go, put them aside for later:
    - How many squares should the player be allowed to move?
    - How will the player interact with objects?
    - How will the conflict be resolved?
  - Try playing it on your own – does the concept work?
    - What questions arise?
    - Avoid adding new rules unless absolutely necessary
    - Keep the core gameplay down to as few rules as possible

<aside class="slide-aside">

- Basic game objects – physical setting, units, resources, etc
- Key procedures – repetitive action cycles that keep the game in motion

</aside>

<div class="image-credit">Physical Prototyping — Fullerton p.217-218</div>

## 2. Structure (building the framework)

- Goal: constructing a structure to support the full feature set
- Prioritise what is most essential to the game
- First decide which rules are essential, which are features that those structural elements need to support
- Features versus rules
  - You can add rules without adding features, but not vice versa
  - One new feature might add 10 or more new rules
  - Focus on rules first and features later
  - Rules tend to be linked to the core gameplay
  - Features tend to be peripheral

<aside class="slide-aside">

- Features – attributes that make a game richer (adding weapons, vehicles, ways to navigate the space)
- Rules – modifications to game mechanics that change how the game functions (winning conditions, conflict resolution, turn order)

</aside>

<div class="image-credit">Physical Prototyping — Fullerton p.231</div>

## 3. Formal details (add rules and procedures)

- Goal: make a fully functional game
- Focus on formal elements to decide what the game needs
  - Is the objective interesting/achievable?
  - Is the player interaction structure the best choice?
  - Are there rules/procedures you want to add that aren't part of the core mechanic?
- Challenge is finding the right level of detail to add
  - New designers usually add too much
  - You want a small, important set of features that all contribute to meeting your experience goal
- Add new rules one at a time and test
  - If the game cannot function without it, leave it in
  - If you can build the game without it, leave it out
  - Can add rules later if they are not essential

<div class="image-credit">Physical Prototyping — Fullerton p.231-232</div>

## 4. Refinement (testing in a controlled environment)

- Goal: to create a compelling game
- Can continue for a number of iterations
- Time to add non-essential ideas/features
  - But don't add them all at once
  - Rank your features in terms of necessity
  - Introduce and test one at a time, then remove it
  - Some great ideas will diminish playability
  - Some that seemed dull will add a new dimension
  - After testing each one, write down an analysis
  - Use your playtesters, incorporate their feedback

## You will need to create a digital prototype for your digital game

- Physical prototypes help think through design and get early feedback, but have limitations
  - Helped formalise and test foundation and mechanics
  - Inform design decisions that you will make
  - Now test essence of game in intended digital format
- Digital prototype – build models of core systems
  - Game logic, special physics, environments, levels
- Envisioning gameplay using input and output devices
  - Control systems – keyboard, mouse, controller, touch, gesture
  - Gameplay as an intuitive, responsive digital interface
- Consider reasons for each prototype
  - Trying to answer game design or technical questions?
  - Establish a production pipeline? Communicate vision?

## Types of digital prototypes

- Mechanics (discrete features of formal aspects)
  - Simple and focused on a particular question
  - Could be via a spreadsheet or other tool
- Aesthetics (visual and aural dramatic elements)
  - Help articulate game mechanics or answer aesthetic questions
  - How will character animation work with the combat system?
  - How will a new interface idea work with the environments?
  - Storyboards – series of drawings, sketch a visual sequence
  - Concept art – paintings/sketch of characters/environments (explore potential looks, palettes, styles for visual aesthetics)

- Still focusing on minimal elements to be functional

- Game Mechanics
- Animatics – animated mock-up of game in action (not using game tech, communicate aesethics and some portion of gameplay)
- Interface prototypes – mock-up of visual interface (can be static or animatic, paper or digital)
- Audio sketches – early draft of music and sound effects (help set the tone and bring life to prototypes)
- Aesthetics - "look, sound"
- Technology

## Types of digital prototypes

- Kinesthetics (feel of the game)
  - How the controls feel, how responsive the interface is
  - Must be prototyped digitally
  - Feel depends on the type of controls (e.g., keyboard vs touch)
  - Some games are entirely about the control schemes
  - Can lead to a whole new game idea
- Technology (making the game work technically)
  - Graphics, AI, physics, other specific problems
  - Testing and debugging tools and workflow
  - Quick and dirty, not the "real" code
