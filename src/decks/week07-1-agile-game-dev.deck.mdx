## Agile Game Development

- Agile is popular with game developers, it is well-suited to the problem of game development, most developers use it in some form
  - Agile is a philosophy, not a prescribed methodology
- Core elements of Agile used by game developers:
  - Flexible goals: not merely tolerating changes to the plan, planning for changes to the plan (we don’t know exactly what we are creating)
  - Prioritised backlog: your backlog is a list of features sorted by priority, things can be added/removed, gets reprioritised each sprint
  - Sprints: a few weeks long, concrete working deliverable at the end
  - Scrum meetings: short (10-15 mins) meetings, standing up, each person reports 3 things: 1) what they did yesterday, 2) what they will do today, 3) what problems they are facing (solutions discussed after meeting)
  - Demo day: everyone gets together at the end of the sprint to see what was produced by the team, creates a new baseline for next sprint
  - Retrospectives: meeting at end of sprint to reflect on the process, what are they doing right/wrong, how to adjust for next sprint

## Agile Game Development

- Adaptive and people-centric software development process
- Address priority features to set short-term goals
- Work together closely to implement goals in short periods - “sprints”
- Meet daily/weekly: evaluate progress, set new goals, identify blockers
- Focus on small interdisciplinary teamwork, communication, input from stakeholders, ongoing implementation, iteration
- Sprints: fixed-length goals for working iterations of the game, goals should be clear/doable and result in playable game, measured in weeks
- Scrum meetings: short daily meetings, team members show progress, set goals for following day, discuss obstacles, led by Scrum Master
  - Often “stand-up” meetings to keep them short (10-15 mins)
- Prioritising: work on features based on input from stakeholders (e.g., players, team, publisher, managers)

## Agile Project Planning

- Project plan includes (feature-based) schedule and budget
- Goals: what are the goals of the project?
  - Gameplay goals - e.g., mechanics, levels, etc
  - Technical goals – e.g., multiplayer
  - Target platform
  - Proposed launch date
- Priorities: organise goals by priorities
  - Core mechanic is highest priority
  - What can/can’t you launch without?
- Schedule: time-bound iterations, usually 2-4 weeks
  - Focus on implementing prioritised features into a working build
  - Overall schedule – estimate of time to implement all features
  - Features are prioritised and worked in sprints as per prioritisation
